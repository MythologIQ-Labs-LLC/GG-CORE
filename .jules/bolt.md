## 2026-02-23 - Lock Iteration Optimizations
**Learning:** In Rust async code, repeatedly acquiring `RwLock` read locks in loops just to recalculate aggregate state (like total memory) can be a hidden bottleneck, especially when the elements can be modified safely without taking the full outer lock for every iteration step. However, refactoring these locks must be done carefully to avoid lock inversions (taking a `write` lock then waiting on a `read` lock inside the block) which causes deadlocks. Also, replacing locks with atomics (`AtomicU64`) on metrics fields is powerful but can be prematurely optimized if the metrics are only in cold paths.
**Action:** Always check the update frequency of locks. Optimize by caching aggregated state outside the loop and updating it decrementally (`saturating_sub`), making sure the method doing the work returns what's needed (e.g. `bytes_freed`) to update the loop state correctly.
