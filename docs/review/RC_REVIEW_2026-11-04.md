# Release-Candidate Review — 2026-11-04

**Question**: is GG-CORE a secure, stable release candidate?
**Baseline**: `main` @ `5e9c2d1` (version 0.9.0, unchanged since 2026-10-05).
**Verdict**: **Not yet.** The core is stable (1,236/0 tests, all CI green at the
last push, zero code churn in a month), but five new RUSTSEC advisories landed
during the idle month, the two disclosed security gaps (daemon sandbox, model
hash verification) are still open, v0.9.0 was never tagged or released, and the
documented vulnerability-reporting channel is still disabled. All are closable;
the punch list is below in order.

## Security findings (new since October)

### S1 — Five RUSTSEC advisories against the current lockfile (gate-failing)

Fresh `cargo deny check` on main **FAILS advisories** today (CI shows green only
because nothing has been pushed since the advisories published):

| Advisory | Crate | Severity/class | Fix |
| --- | --- | --- | --- |
| RUSTSEC-2026-0386 | tokio 1.49.0 | unsound (`AsyncFd` I/O safety) | `cargo update -p tokio` → ≥1.53.3 |
| RUSTSEC-2026-0367/0368/0369/0429 | zip 1.1.4 (via candle-core 0.8.4, `onnx` feature only) | 3 vulns (SUID preservation, symlink escape, symlink perms) + 1 DoS in `ZipArchive::extract` | needs zip ≥9.0.0 |

On the zip set: PR #121 (candle 0.11, **fully green CI**) moves zip to 8.6.0 —
still <9. After merging #121, try `cargo update -p zip`; if candle 0.11
constrains zip below 9, add documented `deny.toml` ignores: GG-CORE never calls
`ZipArchive::extract` (candle uses zip to *read* .npz entries, not extract to
disk), so the vulnerable code path is unreachable here — revisit on the next
candle bump. Exploitability in GG-CORE: negligible; gate hygiene: required.

### S2 — The two disclosed security gaps are still open (unchanged main)

Verified again today:
- **Daemon never applies the sandbox** — `create_sandbox` has no caller outside
  tests. For a security-first runtime, an RC should either wire it into `serve`
  startup or ship with the SECURITY.md caveat prominently in the release notes.
- **Model `sha256` never verified** — manifest field is length-checked only;
  `ModelHashMismatch` is never emitted. SECURITY.md says "do not rely on
  manifest hashes" — honest, but enforcement is the RC-grade fix.

These are ROADMAP near-term #1 and #2 and the top code work between here and RC.

### S3 — Private vulnerability reporting still disabled

SECURITY.md (merged 2026-10-05) directs reports to GitHub private vulnerability
reporting; the API confirms `enabled: false`. One click: Settings → Code
security → Private vulnerability reporting. Until then the published policy
points at a dead channel.

### S4 — Latent flaky security test (stability)

`security_audit::crypto_tests::swapped_ciphertext_fails` swaps `ciphertext[0]`
with `ciphertext[mid]`; when those bytes happen to be equal (~0.4%/run — the
nonce randomizes ciphertext), the swap is a no-op, decryption succeeds, and the
test fails. This already produced a false red on PR #123 (blamed on a tempfile
bump). Fix: deterministic tamper (XOR a byte when the swap would be a no-op).

## Path to RC (recommended order)

1. **Advisory sweep** (small PR): `cargo update -p tokio`; merge #121; then
   `cargo update -p zip` or documented deny.toml ignores for the zip set; fix
   the S4 flake in the same PR. Gets the supply-chain gate green again.
2. **Merge the easy green Dependabot PRs** (#117, #118, #119, #122; #123 after
   rebase). Close draft #111.
3. **Enable private vulnerability reporting** (owner, one click).
4. **Sandbox wiring + hash enforcement** (S2) — the two L3 code items; each is
   a scoped PR with security tests. This is what makes "secure RC" true rather
   than merely disclosed.
5. **RustCrypto migration** (#120) → then #124 (llama-cpp-2).
6. **MSRV/toolchain pin** (still floating; bit us once already).
7. **Cut the release**: with 1–4 landed, bump to 0.9.1 (or 0.10.0 if #121 is
   deemed minor-worthy), tag, and let the never-yet-exercised release pipeline
   produce the first artifacts. Tag push remains an owner action (this session
   type cannot create tags).

Items 1–2 are an afternoon; item 4 is the substantive work; everything else is
clicks and process.

## What is already RC-grade

Worth stating: the test base (1,236 tests incl. an 85-test penetration suite on
3 OSes), the supply-chain gate, the secure-façade architecture (sole inference
path, path confinement, authenticated lifecycle), model-gated readiness,
honest documentation, and a verified release pipeline design. The distance to
RC is the punch list above, not structural work.
