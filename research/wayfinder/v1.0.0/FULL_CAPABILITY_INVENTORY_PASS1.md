## Interpretation

This inventory enumerates **all 63 rows currently present in the historical Feature Index** (F-18 is a retired ID, **not an automatically missing feature**), plus 28 cross-cutting or not-in-index candidate capabilities. `FEATURE_INDEX` labels all 63 as `verified`; that label means a code/test binding was recorded, **NOT** that the capability is exposed in a published, secure standalone runtime or qualified on every OS/hardware/model. The broader statuses are inferred from the frozen release contract/roadmap, not fresh execution of each source file; any row not tied to a full package receipt must remain unqualified pending independent testing.

All previously discussed capabilities are **presumptively IN for review**. A recommended owner disposition here is *review*, **not approval of every suggested implementation**. Research-only ideas, features better owned by a host, and cross-platform assurance requirements must receive explicit owner disposition at #160. A truthful supported-matrix subset is not a silent license to omit a promised v1 feature.

## C. Direct code-grounded counterexamples to “verified means ready”

- [`multi_gpu_exec.rs`](https://github.com/MythologIQ-Labs-LLC/GG-CORE/blob/fd9ee79574dfca8ba860b2e579bbce5555f0c6b0/core-runtime/src/engine/multi_gpu_exec.rs) simulates forward passes and compute delay in its multi-GPU executors. **F-16 cannot count as multi-GPU inference.**
- [`gguf/mod.rs`](https://github.com/MythologIQ-Labs-LLC/GG-CORE/blob/fd9ee79574dfca8ba860b2e579bbce5555f0c6b0/core-runtime/src/engine/gguf/mod.rs) defaults to `n_gpu_layers: 0` with a CPU-only comment. **The packaged GGUF runtime is not CUDA/Metal qualified**, regardless of GPU detection.
- [`memory/paged.rs`](https://github.com/MythologIQ-Labs-LLC/GG-CORE/blob/fd9ee79574dfca8ba860b2e579bbce5555f0c6b0/core-runtime/src/memory/paged.rs) implements a genuine page-pool library, but the frozen roadmap says no serving-path caller. **F-21 does not prove paged KV inference is operating.**
- [`flash_attn.rs`](https://github.com/MythologIQ-Labs-LLC/GG-CORE/blob/fd9ee79574dfca8ba860b2e579bbce5555f0c6b0/core-runtime/src/engine/flash_attn.rs) begins with "**CPU Flash Attention implementation**"; distinguish this from missing **GPU flash-attention kernels**. Do not wrongly dismiss CPU code as a universal stub or infer GPU support.
- [`ipc/listener.rs`](https://github.com/MythologIQ-Labs-LLC/GG-CORE/blob/fd9ee79574dfca8ba860b2e579bbce5555f0c6b0/core-runtime/src/ipc/listener.rs) is a real Windows named-pipe listener, but simultaneous clean guest clients produced `ERROR_PIPE_BUSY` failures under [#163](https://github.com/MythologIQ-Labs-LLC/GG-CORE/issues/163), so "connection management verified" is an incomplete operational claim.
- [#162](https://github.com/MythologIQ-Labs-LLC/GG-CORE/issues/162) proves the current Windows archive cannot launch in a pristine Windows Sandbox without the missing signed MSVC/OpenMP redistributables. Release CI on images with dependencies installed is insufficient.

## D. Model-quality results cannot be inferred from functional inference

The [Windows baseline #156](https://github.com/MythologIQ-Labs-LLC/GG-CORE/issues/156#issuecomment-6690245052) ran six exact synthetic fixtures, all failed their content rubric with a raw-prompt 0.5B instruct model despite functioning secure IPC and long-context stability. Likely reasons are missing per-model chat template and the model's small capacity, but that is a **hypothesis**, not a proven root cause. Explicitly compare same weight/sampling with proper official template and larger license-checked model(s). Only promote quality-tier routing after real task acceptance and owner quality floors.
